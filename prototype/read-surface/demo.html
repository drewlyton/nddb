What reads should the handle expose?

A materialised view is a Map, so almost every proposed read is one line over it. The question is which of those one-liners are worth naming. This demo runs each candidate read, counts how many entity copies it performs under #6's copy-on-read rule, and shows what three honest call sites actually need: render a list, look one up by id, filter by hand.

The predicate hazard

If filter/find call your predicate with the stored entity, a predicate that mutates corrupts the view — the same trap #6 closed for get. The only safe version copies before calling you, which is exactly all().filter(...).
